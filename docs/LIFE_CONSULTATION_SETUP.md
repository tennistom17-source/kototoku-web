# コトトク 多視点相談室：質問文作成と将来の接続設計

状態：質問文作成版を実装、2026-09-14に公開承認済み。以前の固定回答版は公開済み。API、サーバー、課金、キー発行は未実施。

## 今回の範囲

- `life-consultation.html`：悩み、3役のチェック選択、生成AIの選択、編集可能な質問文、コピー・外部リンク、安全案内。
- `assets/css/life-consultation.css`：ページ内に限定したスタイル。PCは入力と回答の2列、800px以下は1列。
- `assets/js/life-consultation.js`：5役から異なる3役を選択。最初は3役を選択済み。未選択の役は3役到達時に無効になり、入れ替えは一つ外して行う。5役×5ジャンルの固定整理例を添えて質問文を作る。本文の理解・AI回答の生成は行わない。
- 入力はDOMと実行中のメモリだけで扱う。fetch、解析タグ、Cookie、localStorage、外部SDKは使用しない。リセットで入力・表示を消す。
- 質問文作成は回数制限なし。以前の3回停止・月間停止・接続エラーの模擬表示は削除。APIを使用せず、コトトク側のAPI費用は発生しない。将来APIを導入する場合の予算制限とは別。
- 入力や生成AIの選択を変えると以前の質問文・リンクを消す。リセット時も本文・質問文を消し、初期の3役とChatGPTを選択し直す。クリップボードや外部サービスの履歴を消す機能ではない。
- トップとサイト案内の紹介文も質問文作成に合わせる。Push・公開は別途承認が必要。
- 既存方針は静的・低保守で医療・法律・安全上の重大判断を扱わない。本件は一般的な悩みを整理する質問文の作成と、将来構成の検討に限る。サーバー導入・データ処理・有料利用は別途承認が必要。

## 画面と確認方法

```text
利用者 → ブラウザ内で質問文作成 → 確認・編集 → コピー
                                                 ↓ 利用者が操作
                             自分の生成AIを開く → 貼り付けて送信

PC：相談フォーム | 質問文・コピー・選択したAIへのリンク
スマホ：相談フォーム → 質問文 → 折りたたみの固定整理例
```

`life-consultation.html` は直接ブラウザで開ける。HTTP配信でも動く。質問文作成に通信サーバーは必須ではない。

1. 600文字以内の架空の悩みとジャンル、3役、生成AIを選び「生成AIへの質問文をつくる」。0〜2役・4役以上は拒否する。
2. 質問文に本文・役・固定例の注意書き・確認質問3つを求める依頼が含まれることを確認する。
3. 質問文を編集してコピー。Clipboard APIを利用できない場合はテキストを選択し、手動コピーを案内する。コピー成功と偽って表示しない。
4. ChatGPT・Gemini・Claude・Microsoft Copilotは固定のHTTPSリンク。「その他」はリンクなし。相談本文をクエリやハッシュに入れない。noopener/noreferrerを付ける。宛先以外は共通の質問形式であり、モデル別最適化をうたわない。
5. 入力または編集した質問文で対象外の危険語を検出したら質問文と通常のリンクを隠し、支援案内を表示する。自前の安全注意文だけは検出対象から除く。検出漏れ・過剰検出があるため安全の保証はしない。窓口番号は固定しない。
6. 「入力と質問文を消す」で初期化。コピーの非同期処理中に入力を変えた場合、古いコピー完了通知を表示しない。

| 利用先 | 料金・履歴の扱い |
| --- | --- |
| このページ | ローカルで質問文を組み立てるだけ。APIキー不要、API費用なし |
| 自分のChatGPTなど | 利用者の契約・利用制限・保存や学習の設定に従う。運営者のChatGPTと接続しない |
| GitHub Copilot | 開発支援用の別サービス。このツールでクレジットを使わない |
| 将来のOpenAI API | 専用の別契約・従量料金。ChatGPTやCopilotの契約に含まれるとみなさない |

クリップボードは端末の履歴・同期に残る場合がある。生成AIへ貼り付けた後は、そのサービスのデータ取扱いが適用される。外部リンクを開くだけでもアクセス情報は移動先へ伝わる。本文の自動送信はしない。APIキー・個人情報・機密をサンプルへ入れない。

公開前チェック：3役選択、全生成AIの宛先、空白入力、コピー成功・失敗、編集反映、古い出力の消去、危険入力、キーボード、スマホ幅、外部通信なしを確認する。今後の候補は短縮版、確認質問の選び方、架空例の追加。未承認では実装しない。

以下は将来の有料API構成の検討資料であり、今回の質問文作成ツールには適用・接続していない。

## 承認後の推奨構成（未実装）

```text
GitHub Pages（画面、キーなし）
  → HTTPS POST /consult（本文はURLに入れない）
  → サーバーレス関数（例：Cloudflare Workers）
      → 強い整合性の予算台帳（例：単一Durable Object）
      → 入力の安全判定
      → OpenAI Responses API（3役と統合を1リクエスト）
      → 出力の構造・安全判定
  ← 構造化JSON または停止・安全案内
```

- ホスティング候補の無料枠・台帳利用可否を契約時に検証する。有料プラン必須で合計1,000円を守れない場合は接続しない。別候補へ自動切替しない。
- APIキーは専用OpenAIプロジェクトの最小権限キーを採用し、サーバーレス事業者のSecret管理画面で運営者が登録する。チャット、HTML、JS、GitHub、Actions出力、画像、ブラウザ入力へ渡さない。
- フロントに置くのは公開エンドポイントURLのみ。ビルド時にキーを埋め込まない。キーを要求する画面を作らない。
- 専用プロジェクトのキーを他用途で共有しない。失効・ローテーション・緊急停止手順を用意する。
- ChatGPTの個人履歴、メモリ、ブラウザCookie、会話IDを取り込まない。ChatGPTの契約とAPI利用料金は別。APIへ送るのはこの相談1件と選択項目・固定指示のみ。過去会話の連結、ファイル検索、個人ChatGPTとのコネクターは使用しない。
- `store: false` を指定し、自前のアプリでは相談本文・回答を保存しない。ただしAPI提供側の不正利用監視等の保持がゼロになる保証ではない。送信前にOpenAIとホスティング側の最新のデータ取扱いを示し、利用者の明示同意を取る。
- 公式データ管理資料では、APIデータは明示的に共有へ同意しない限り学習に使用されない。一方、不正利用監視ログは通常最大30日保持され、法令・安全上の理由による延長がある。`store: false` と学習不使用は別の制御であり、どちらも無保持を意味しない。モデル別のキャッシュ保持条件も確認する。Zero Data Retentionは申請・承認が必要なため、今回利用できると仮定しない。
- 年齢・性別は相談役の人物像であり利用者属性ではない。能力・価値観の決めつけに使わず、3役は観点で差を付ける。架空の役割であることを各結果に明記する。

## 月1,000円の概算と受付上限

まずは「サイト全体で月100件、1日10件」の小規模試行を提案する。利用者ごとに100件ではない。

| 項目 | 初期提案 |
| --- | --- |
| 悩み本文 | 1〜600文字、空白だけは不可、サーバーで再検証 |
| リクエスト全体 | 最大8KiB、選択値は列挙値に制限 |
| AI入力 | 固定指示・JSON形式込みで最大2,500トークン、超過時は拒否 |
| AI出力 | 最大1,200トークン（推論等を含む課金対象の扱いをモデル別に確認） |
| 役割 | 3意見と統合を1回で生成、履歴なし・ツールなし・検索なし |
| 受付 | 全体100件/月、10件/日、同時処理1件 |
| 連打対策 | 1セッション60秒に1件、日3件を補助制限 |
| API費用台帳 | 月600円を予約上限とし、残り400円は税・為替・基盤の余裕 |
| 自動再試行 | なし。失敗時も課金の可能性を考慮 |

価格は変わるため、モデル名・料金をここで固定して契約しない。接続時に構造化出力・安全判定に適した低価格モデルを選び承認を得る。

**計算用の仮定（実モデルの見積書ではない）**：入力$1/100万トークン以下、出力$5/100万トークン以下、換算180円/$、税等の余裕10%。キャッシュ割引は数えない。

`(2,500 × 1 + 1,200 × 5) / 1,000,000 × 180 × 1.10 = 約1.69円/生成`

入力・出力の安全判定、失敗分の余裕を含め、最初は **1相談6円を事前予約、全体100件で600円** とする。ただし安全判定の価格と回数も公式料金で積算し、6円に収まることが接続条件。超える場合は回数を減らすか受付を閉じ、上限を黙って変更しない。

残り400円にホスティング費・税・換算差額が収まるか確認する。基盤のリクエスト従量課金や攻撃時の課金も対象。無料枠超過時に従量課金される契約では「必ず1,000円以内」と保証できないため、無料枠で停止する構成が確保できない限り公開APIを開始しない。

OpenAI管理画面の予算通知だけをハード停止とみなさない。為替・単価改定・他経路の利用に対する無条件の円建て保証ではない。上記前提を確認できない月は停止のままとする。

## 同時アクセスでも超過させない受付処理

1. サーバー時計をAsia/Tokyoで評価し、月キー `YYYY-MM` と翌月1日00:00 JSTを計算。クライアント時計を信用しない。
2. メソッド、本文サイズ、列挙値、同意、レート制限、ボット対策を検証。CORSは公開サイトの正確なOriginだけを許すが、認証や費用制御の代わりではない。
3. 台帳の同一トランザクション内で有効化フラグ、価格設定期限、月件数、日件数、使用額＋予約額を確認する。`使用額 + 未確定予約額 + 今回の最大額 > 600円` または100件到達なら拒否。条件を満たす場合だけ、ランダムなリクエストIDで予約し受付件数を加算する。
4. 予約は安全判定APIより前に行う。台帳障害・単価不明・上限不明ならfail closedで外部APIを一切呼ばない。
5. SDK自動リトライを無効にし、入力安全判定→生成→出力安全判定の各最大費用を予約枠内で実行。明確な危険は生成せず固定の窓口案内だけを返す。
6. usageから確定額を保守的に計上し、確実に分かった未使用額だけ解放する。タイムアウト・接続切断・応答紛失では最大予約を維持する。期限切れだけを理由に予約を返金しない。再送は同じIDで追加呼出ししない。
7. 安全拒否・失敗も受付件数を消費する。本番でクライアントから回数をリセットできるAPIを作らない。複数リージョンで別々の台帳を作らない。
8. 翌月は新しい月台帳を作る。前月の未確定分・債務は削除せず、安全確認が済むまで翌月も必要に応じて停止。日付だけでキーや履歴を消さない。

利用者別制限をログインなしで厳密に守らせることはできない。Cookie削除・IP変更が可能なため、必ず全体予算を最終防壁にする。IPの永続保存は避け、必要な場合は事業者のレート制限または短期・ローテーション済みハッシュを検討し、識別子としての取扱いも承認を得る。ボット対策サービス導入も通信・費用の追加承認が必要。

## API契約と表示状態

- `POST /consult`：`concern, genre, advisors: [advisorA, advisorB, advisorC], consent, requestId`。各相談役はサーバーが定義した許可済みタイプから選ぶ。model、max_output_tokens、指示文、URLなどを利用者から受け取らない。
- 成功：`mode: live, advisors: [{id, perspective, opinion}]`（厳密に3件）、`common, differences, nextStep`。JSON Schemaで型・長さ・件数を検証する。
- 月停止：HTTP429、`code: MONTHLY_LIMIT, retryAt`。画面は「月間の利用上限に達しました。次の受付予定：○月1日（日本時間）」、ボタン無効。日・短期制限は別コードと再開時刻。
- 安全案内：`code: SAFETY_REFERRAL`、一般回答なし。緊急時は119/110（日本）または現地緊急窓口。医療・法律判断は適切な専門家へ。
- 障害：503/504。ボタン復帰前に予約状態を照合。自動再送・別モデルへの自動切替・固定回答での代替はしない。
- 送信中は二重送信を禁止。HTTP応答に `Cache-Control: no-store` を付け、入力・回答をURL、解析イベント、エラーログへ入れない。
- API未設定時は質問文作成のみとし、設定済みでも同意前は送信不可。本番失敗を固定回答で隠さない。今回のJSは接続コード自体を含まない。

## 安全・プライバシーの公開条件

- 自傷・他害・暴力・虐待・差し迫った危険は一般的な3意見に変換しない。緊急支援を優先し、相手への対決など危険を増す行動を促さない。
- 医療診断・薬の判断・法的結論は扱わない。専用安全判定とモデル指示、出力検証を組み合わせる。キーワードだけ、モデルへの注意文だけでは不十分。
- 危険語のない遠回しな表現、誤検出、未成年、虐待の文脈を含む日本語評価を実施する。判断不能・判定障害は安全案内へ。危険な内容の具体例を公開ログへ残さない。
- 悩みは機微情報を含み得る。「個人情報を入力しない」だけでは匿名性は保証できない。送信同意と、第三者・OpenAI・基盤の取扱いを明示する。
- プロキシ・WAF・APM・例外通知・アクセスログを含め本文記録を無効にする。台帳は金額・件数・トークン数・ランダムID・状態のみ。識別子は再送判定用に48時間程度、月次集計は請求確認に必要な期間（案：90日）とし、正式に決めて公開する。
- 外部への漏洩を避け、入力やAI出力は `textContent` で描画。Markdownの生HTML・外部画像・自動リンク埋込は使わない。CSP等のヘッダーは公開方式に合わせて設定する。
- 初回は限定的なテスト参加者で検証する。本番公開は安全性・費用制御・データ取扱いの審査後。継続的な専門家の代替や緊急受付として宣伝しない。
