# コトトク 多視点相談室：OpenAI接続手順

## 現在の状態

2026-09-14、運営者は「OpenAI APIを使って相談に応じた3役の言葉・短いまとめ・引き継ぎプロンプトを生成する」「サイト全体で毎月1,000円以内」「予算停止機能付きサーバーレス処理の追加」を承認。定型の相談回答は使用しない。

コードはGitHubへ公開済み。2026-09-14にCloudflare Workerも `ENABLED=false` の停止設定で配置した。公開ページにはWorkerの `/consult` URLだけを設定し、Secret・契約条件の確認は未完了のため、`consultation-ready=false` により送信を止めている。Cloudflareの `workers.dev` サブドメイン登録も未完了のため、Worker URLはTLS接続できない。実際の請求額・残高・1,000円での課金停止を確認した状態ではない。

## 実装した流れ

```text
相談本文・3役・ジャンル・引き継ぎ先・明示同意
  → HTTPS POST /consult
  → Cloudflare Worker → 単一SQLite Durable Objectで予算を確保
  → OpenAI入力安全判定 → Responses API 1回 → 出力安全判定
  → 3役の考え方・問い・行動 → 簡潔な共通点・相違点・一歩
  → AIが作った引き継ぎ文を確認・編集・コピー
  → 利用者自身が選択した生成AIを開いて貼り付ける
```

- `api/consultation.mjs`：入口・予算台帳・OpenAI通信・構造検証。
- `api/wrangler.jsonc`：SQLite Durable Objectと停止中の設定。秘密情報は入れない。
- `api/consultation.test.mjs`：ネットワークを模擬した予算・生成の単体テスト。
- `assets/js/life-consultation.js`：同意後の送信、実際の応答だけの表示、コピー、引き継ぎリンク。
- API未設定、期限切れ、上限、通信障害、不正出力は停止。安全窓口・エラーメッセージだけは固定表示。停止中は、入力内容を使わず外部へ送らない固定の例を表示できる。
- OpenAIが3役を担当する。移動先でGemini等を選んでも、その会社を最初の生成に使うわけではない。

### 利用者への説明と受付休止の表示

- 同意欄の直前に、Cloudflareを「受付・中継サービス」、OpenAIを「回答を考えるAI」と説明する。送信操作、利用枠確認、AI生成、利用者自身による引き継ぎの4段階を常時表示する。
- 相談内容が外部の2社で処理されること、アプリの非保存と提供側の保持は別であること、会員登録と料金の扱いを明示する。同意をチェックするだけでは送信しない。
- フォーム上部に受付状態を表示。未設定、月上限、日上限、料金確認中では「今は使えません」と理由・再開の条件を示し、生成ボタンも無効にする。
- サーバーから停止コードを受けた後は、入力・選択・リセットで停止状態を解除しない。応答待ち中に本文を変えた場合も、古い回答は表示しないが全体枠の停止通知は反映する。
- 月上限は翌月以降の運営者による予算確認が必要。日上限は翌日（日本時間）以降の再試行を案内するが、月上限などの継続停止の可能性も伝える。
- ページ読込時の残高照会や停止状態のブラウザ保存はしない。接続設定があるページでは送信時に全体枠を確認する。再読込してもサーバーの予算は復活しない。混雑・一般的な通信失敗は恒久的な予算停止と区別する。
- 接続先は `https://kototoku-consultation.ototoku--aini-roject.workers.dev/consult`。`consultation-ready=false` の間はブラウザからWorkerへ送信しない。Workerが `FORBIDDEN` を返しても利用者には「現在は準備中です」と表示する。
- 模擬テストでは4種類の停止コード、リセット後の再送ゼロ、入力変更中の停止通知、同意だけで送信しないこと、説明リンクとスマートフォン表示を確認する。

## 予算を止める条件

| 項目 | 現在の実装 |
| --- | --- |
| 全体枠 | 月100件・日10件、全体で60秒間隔、処理ロック120秒 |
| 予約 | API呼出しより先に1件6円を永続台帳へ確保。月600円で停止 |
| 失敗 | 失敗・拒否・タイムアウトでも予約は戻さない。成功も6円のまま |
| 余裕 | 月1,000円から残り400円を税・為替・基盤費の余裕として残す |
| 入力 | 本文600文字、HTTP本文8KiB。生成リクエストのUTF-8バイト数＋内部形式の余裕4,096を12,000以下に制限 |
| 出力 | `max_output_tokens=2400`、ツールなし、1回の生成、標準処理 |
| 確認期限 | JSTの対象月・料金確認期限が不一致なら停止。翌月は自動再開しない |
| 異常 | 台帳障害では外部呼出しなし。課金トークン数が不明・想定超過なら永続holdで以後も停止 |
| 再送 | 同一月の同一受付IDを拒否。ブラウザ・サーバーとも自動再試行なし |

モデルは `gpt-4.1-mini-2025-04-14` に限定。公式価格表のgpt-4.1-miniは入力$0.40/100万、出力$1.60/100万、moderationは無料と確認（2026-09-14）。実際に利用できるモデルIDと料金は接続時も確認する。

円換算の初期値198円/$は180円×1.10の保守的な計算用仮定であり現在レートではない。12,000入力・2,400出力なら約1.72円を見込み、6円を予約する。割引は数えない。入力バイト数によるトークン上界の仮定も選んだ固定モデルで実環境確認が必要。単価・為替が前提を超える場合は停止して見直す。

これはアプリの予約台帳であり、OpenAIの請求額との自動照合や口座全体の円建てハード上限ではない。同じキー・プロジェクトを別用途に使わない。別経路の課金・単価変更・契約変更までは制御できない。

Cloudflare公式資料ではWorkers FreeでSQLite Durable Objectsを利用でき、無料枠超過時はエラーになる。**運営者の実アカウントがWorkers Freeで、他の有料オプションを使わないことの確認が必要。** Paidへの変更は無断で行わない。CORSはアクセス認証ではなく、攻撃でも全体枠は消費され得る。消費済みの枠を消して再開しない。

## 初回接続の手順

1. Node.js LTSとnpmを用意する。この作業環境ではNode.js LTSを導入済みで、Wranglerの `--dry-run` ビルド検証は成功した。実環境の相談リクエスト試験は未実施。
2. CloudflareアカウントのWorkers Freeと無料枠停止条件、OpenAIの専用プロジェクト・料金・残高を運営者が確認する。既存ChatGPT・Copilot契約の枠とは別。
3. リポジトリルートから `npx wrangler@4 deploy --dry-run --config api/wrangler.jsonc` でビルド検証。アカウントのログインは運営者自身で行う。
4. 配備承認後、`ENABLED=false` のまま `npx wrangler@4 deploy --config api/wrangler.jsonc`。公開URLを得る。初回に `workers.dev` サブドメインの登録を求められた場合は、Cloudflareダッシュボードで登録してからURLへHTTPS接続できることを確認する。
5. CloudflareのWorker設定にSecret `OPENAI_API_KEY` を運営者自身で登録する。チャット、HTML、GitHub、設定ファイル、スクリーンショットへキーを貼らない。必要なら端末で `npx wrangler@4 secret put OPENAI_API_KEY --config api/wrangler.jsonc` を実行し、秘密入力は運営者自身が行う。
6. 設定の各項目を確認する。`FREE_PLAN_VERIFIED`、`MODERATION_FREE_VERIFIED` は確認後だけtrue。`APPROVED_MONTH` はJSTの対象月、`PRICE_VALID_UNTIL` は確認済み料金の有効期限（当月内を推奨）。料金・換算値は保守的に設定する。
7. テスト用の専用基盤でDurable Objectの原子性・再起動後の台帳保持・上限時の外部呼出しゼロを確認する。限定的な実AIテストも同じ予算枠に計上する。危険・遠回しな表現・対象外相談・日本語の応答品質を評価する。
8. 全条件確認後に限り `ENABLED=true`。画面の `<meta name="consultation-api" content="">` に公開HTTPSの `/consult` URLだけを設定。キーは入れない。GitHub Pagesにはバックエンドの実行機能はない。
9. 公開前に送信同意、提供側の保持条件、ログ設定を確認し、運営者が最終承認する。

ブラウザ用CORSは `https://tennistom17-source.github.io` のみに限定。ローカル確認用に本番の許可Originを広げない。緊急停止は `ENABLED=false` に再配備し、必要なら専用APIキーを失効する。すでに送った呼出しは取り消せない。台帳・Durable Objectの名前やnamespaceを変更すると上限が初期化されるため、同じ月に別台帳で再開しない。

## テストとデータ

模擬単体テストはサイトをローカルHTTP配信し、ブラウザで `await (await import('/api/consultation.test.mjs')).runTests()` を実行する。Node.jsがある場合は `node --input-type=module -e "import('./api/consultation.test.mjs').then(async module => console.log(await module.runTests()))"` でも実行できる。キー不要・実API通信なし。

本文・回答をアプリの保存領域やログへ書かない。台帳は月件数・日件数・予約額・ランダムID・受付時刻のみ。現実装では台帳の自動削除なし。請求確認が済んだ過去月だけを運営者が削除でき、当月の枠は消さない。`store:false` は提供側の安全監視等の保持をゼロにする保証ではない。実接続前に適用条件を確認し、入力に同意を必須とする。リセットはクリップボードや提供側の保持データの削除ではない。

## 月1,000円の概算と受付上限

まずは「サイト全体で月100件、1日10件」の小規模試行を提案する。利用者ごとに100件ではない。

| 項目 | 初期提案 |
| --- | --- |
| 悩み本文 | 1〜600文字、空白だけは不可、サーバーで再検証 |
| リクエスト全体 | 最大8KiB、選択値は列挙値に制限 |
| AI入力 | 固定指示・JSON形式込みで最大2,500トークン、超過時は拒否 |
| AI出力 | 最大1,200トークン（推論等を含む課金対象の扱いをモデル別に確認） |
| 役割 | 3意見と統合を1回で生成、履歴なし・ツールなし・検索なし |
| 受付 | 全体100件/月、10件/日、同時処理1件 |
| 連打対策 | 1セッション60秒に1件、日3件を補助制限 |
| API費用台帳 | 月600円を予約上限とし、残り400円は税・為替・基盤の余裕 |
| 自動再試行 | なし。失敗時も課金の可能性を考慮 |

価格は変わるため、モデル名・料金をここで固定して契約しない。接続時に構造化出力・安全判定に適した低価格モデルを選び承認を得る。

**計算用の仮定（実モデルの見積書ではない）**：入力$1/100万トークン以下、出力$5/100万トークン以下、換算180円/$、税等の余裕10%。キャッシュ割引は数えない。

`(2,500 × 1 + 1,200 × 5) / 1,000,000 × 180 × 1.10 = 約1.69円/生成`

入力・出力の安全判定、失敗分の余裕を含め、最初は **1相談6円を事前予約、全体100件で600円** とする。ただし安全判定の価格と回数も公式料金で積算し、6円に収まることが接続条件。超える場合は回数を減らすか受付を閉じ、上限を黙って変更しない。

残り400円にホスティング費・税・換算差額が収まるか確認する。基盤のリクエスト従量課金や攻撃時の課金も対象。無料枠超過時に従量課金される契約では「必ず1,000円以内」と保証できないため、無料枠で停止する構成が確保できない限り公開APIを開始しない。

OpenAI管理画面の予算通知だけをハード停止とみなさない。為替・単価改定・他経路の利用に対する無条件の円建て保証ではない。上記前提を確認できない月は停止のままとする。

## 同時アクセスでも超過させない受付処理

1. サーバー時計をAsia/Tokyoで評価し、月キー `YYYY-MM` と翌月1日00:00 JSTを計算。クライアント時計を信用しない。
2. メソッド、本文サイズ、列挙値、同意、レート制限、ボット対策を検証。CORSは公開サイトの正確なOriginだけを許すが、認証や費用制御の代わりではない。
3. 台帳の同一トランザクション内で有効化フラグ、価格設定期限、月件数、日件数、使用額＋予約額を確認する。`使用額 + 未確定予約額 + 今回の最大額 > 600円` または100件到達なら拒否。条件を満たす場合だけ、ランダムなリクエストIDで予約し受付件数を加算する。
4. 予約は安全判定APIより前に行う。台帳障害・単価不明・上限不明ならfail closedで外部APIを一切呼ばない。
5. SDK自動リトライを無効にし、入力安全判定→生成→出力安全判定の各最大費用を予約枠内で実行。明確な危険は生成せず固定の窓口案内だけを返す。
6. usageから確定額を保守的に計上し、確実に分かった未使用額だけ解放する。タイムアウト・接続切断・応答紛失では最大予約を維持する。期限切れだけを理由に予約を返金しない。再送は同じIDで追加呼出ししない。
7. 安全拒否・失敗も受付件数を消費する。本番でクライアントから回数をリセットできるAPIを作らない。複数リージョンで別々の台帳を作らない。
8. 翌月は新しい月台帳を作る。前月の未確定分・債務は削除せず、安全確認が済むまで翌月も必要に応じて停止。日付だけでキーや履歴を消さない。

利用者別制限をログインなしで厳密に守らせることはできない。Cookie削除・IP変更が可能なため、必ず全体予算を最終防壁にする。IPの永続保存は避け、必要な場合は事業者のレート制限または短期・ローテーション済みハッシュを検討し、識別子としての取扱いも承認を得る。ボット対策サービス導入も通信・費用の追加承認が必要。

## API契約と表示状態

- `POST /consult`：`concern, genre, advisors: [advisorA, advisorB, advisorC], consent, requestId`。各相談役はサーバーが定義した許可済みタイプから選ぶ。model、max_output_tokens、指示文、URLなどを利用者から受け取らない。
- 成功：`mode: live, advisors: [{id, perspective, opinion}]`（厳密に3件）、`common, differences, nextStep`。JSON Schemaで型・長さ・件数を検証する。
- 月停止：HTTP429、`code: MONTHLY_LIMIT, retryAt`。画面は「月間の利用上限に達しました。次の受付予定：○月1日（日本時間）」、ボタン無効。日・短期制限は別コードと再開時刻。
- 安全案内：`code: SAFETY_REFERRAL`、一般回答なし。緊急時は119/110（日本）または現地緊急窓口。医療・法律判断は適切な専門家へ。
- 障害：503/504。ボタン復帰前に予約状態を照合。自動再送・別モデルへの自動切替・固定回答での代替はしない。
- 送信中は二重送信を禁止。HTTP応答に `Cache-Control: no-store` を付け、入力・回答をURL、解析イベント、エラーログへ入れない。
- API未設定時は質問文作成のみとし、設定済みでも同意前は送信不可。本番失敗を固定回答で隠さない。今回のJSは接続コード自体を含まない。

## 安全・プライバシーの公開条件

- 自傷・他害・暴力・虐待・差し迫った危険は一般的な3意見に変換しない。緊急支援を優先し、相手への対決など危険を増す行動を促さない。
- 医療診断・薬の判断・法的結論は扱わない。専用安全判定とモデル指示、出力検証を組み合わせる。キーワードだけ、モデルへの注意文だけでは不十分。
- 危険語のない遠回しな表現、誤検出、未成年、虐待の文脈を含む日本語評価を実施する。判断不能・判定障害は安全案内へ。危険な内容の具体例を公開ログへ残さない。
- 悩みは機微情報を含み得る。「個人情報を入力しない」だけでは匿名性は保証できない。送信同意と、第三者・OpenAI・基盤の取扱いを明示する。
- プロキシ・WAF・APM・例外通知・アクセスログを含め本文記録を無効にする。台帳は金額・件数・トークン数・ランダムID・状態のみ。識別子は再送判定用に48時間程度、月次集計は請求確認に必要な期間（案：90日）とし、正式に決めて公開する。
- 外部への漏洩を避け、入力やAI出力は `textContent` で描画。Markdownの生HTML・外部画像・自動リンク埋込は使わない。CSP等のヘッダーは公開方式に合わせて設定する。
- 初回は限定的なテスト参加者で検証する。本番公開は安全性・費用制御・データ取扱いの審査後。継続的な専門家の代替や緊急受付として宣伝しない。
