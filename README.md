# kototoku-web
「できるを、もっと身近に。」個人がAIと一緒に小さなWebプロジェクトを育てる記録サイト。

このサイトは実在企業の公式サイトではありません。個人が運営する実験的なWebプロジェクトです。
「AIチーム」に登場するメンバーは実在の人物ではなく、AIの役割設定を分かりやすくするための架空の設定です。

## ページ構成

- `index.html`：ホーム。組織の仕組み、AIチーム、活動ログ、匿名日記の抜粋、将来への関係図、動画、サイト概要、小さなツール、安心への取り組み。
- `diary.html`：つくる日記。個人情報を出さずに、AIと小さな挑戦を始める記録。
- `ai-company.html`：AIチーム。運営者が最終判断を行う、架空の役割設定。既存URLを維持。
- `faq.html`：よくある質問。GitHub Pagesでの公開やAIチームについてのQ&A。
- `site-map.html`：閲覧者向けのサイト案内。各ページ・主要セクションを部屋に見立てたフロアマップ。全ページのナビゲーションから移動できる。
- `ai-model-compare.html`：生成AI・モデル比較と使い方診断。回答はブラウザ内だけで点数化し、保存・送信しない。
- `site.css` / `site.js`：全ページ共通のデザインとメニュー・動画エラー表示処理。

## AI比較診断

- `assets/css/ai-model-compare.css`：比較ページ専用のレスポンシブスタイル。
- `assets/js/ai-model-compare.js`：JSONを読み込み、ルールベースで診断、SVGのレーダー・バブルチャート、用途別の横棒グラフを表示。外部JavaScriptライブラリやAPIキーは使わない。
- `data/models.json`：表示するサービス・モデル、プランの目安、公式URL、公式情報URL、最終確認日、用途別比較評価。評価は絶対的な性能順位ではない。
- `data/scoring-rules.json`：質問の回答ごとに用途別の能力値へ加える重み、既存利用サービスの加点、「要評価」モデルの減点を管理。診断規則をJavaScriptへ直接書かない。
- 初期データの価格・モデル名は、2026-09-14に取得した各サービスの公式価格・製品ページで確認できた内容だけを記載。地域、税、利用上限、提供状況は変動するため、契約前にリンク先の公式情報を確認する。
- `evaluation_status` が `要評価` のデータは、公式ページ上のサービス・プランを確認できても、コトトク内の能力評価を人が確定していない項目。診断では減点し、最上位に出にくくする。

### 自動更新

- `scripts/update_models.py` は、各データの `source_url` だけを取得する。公式ページを安全に構造化して確認できない場合、モデル名・料金・提供状況・能力値を推測で書き換えない。
- 取得失敗時は `models.json` の `last_checked` を更新せず、標準出力と `data/update-log.json` に取得失敗理由を残す。能力値は自動更新しない。
- 新しいモデルの自動追加もしない。人が公式情報を確認して `evaluation_status: "要評価"` として追加し、評価後に点数を設定する。
- `.github/workflows/update-model-data.yml` は毎日1回（UTC 02:17）と手動実行でPythonを実行する。`models.json` に検証済みの差分が発生した場合だけ、更新ログとともに自動コミット・pushする。今回の運用では、この自動公開を明示的な例外として採用している。
- 実行失敗はGitHubの `Actions` からワークフロー `Update official AI model data` を開き、`Check official sources and update safe fields` のログを確認する。Actionがpushできない時は、リポジトリの `Settings` → `Actions` → `General` で `Workflow permissions` の書き込み権限を確認する。
- ローカルで確認する場合は、リポジトリ直下で `python scripts/update_models.py` を実行する。比較画面はJSON読み込みがあるため、`python -m http.server 8765 --bind 127.0.0.1` で配信して確認する。

## デザイン更新

- 白と青を維持し、ブランド名・タイポグラフィ・余白・罫線を中心としたプロダクトメディア風の構成に更新。
- ホームのファーストビュー直下に組織の仕組みを配置。既存のブランドムービーと各セクション・リンクは、その後に維持。
- カードの過剰な囲みを減らし、ナビゲーション、フッター、下層ページも共通の見た目に統一。
- スマホのメニュー開閉、Escキー、フォーカス表示、動きを減らす設定に対応。
- 公開文言を「AIチーム」に統一。匿名性の注記・個人運営であること・準備中の表示を維持。
- 外部画像・外部フォント・外部ライブラリ・計測・フォーム・会員登録は追加していない。

## 組織紹介の更新（2026-09-14）

- 白と青を基調に、AIの作業は青、人の判断は緑、記録と学びはローズで区別。ノート・虫眼鏡・確認印・本をHTML/CSSで図案化。
- 作業の6工程はPCで横並び、1000px以下では順序を追いやすい縦並び。図は運用方針であり、自律稼働の実績ではない。
- 公開ルールを維持し、「AIチーム」とイニシャルのみ使用。公開済みの5名の役割を紹介し、全10名の紹介へリンク。人物画像は両ページとも役割を表す小物図案へ変更。内部名簿・モデル設定・管理ログは転載しない。
- 活動ログは日時・担当AI・提案・社長の判断の4列。4項目を確認できる公開用記録がないため準備中とし、例示の日時や活動を掲載しない。追加時は根拠と公開承認を確認する。
- 日記の3つの抜粋は公開済み記事の要約。`diary.html#day-000` と `diary.html#day-001` へ直接リンク。
- 組織・日記・ツール・信頼・将来の収益化の関係図を追加。ツールや収益は実績ではなく、準備中・検討段階と明記。
- JavaScriptが無効でも本文とナビゲーションを表示。動きを減らす設定に対応。既存の計測タグは変更していない。

### 小物イラストと日記の要約

- トップ5件・AIチーム紹介10件を、共通のHTML/CSS小物イラストに統一。虫眼鏡、ノート、モニター、フラスコ、チェックリスト、設計図、スマートフォン、南京錠で役割を表現。
- 図案には `role="img"` と日本語の代替説明を指定。旧人物画像ファイルは削除せず、ページからの参照のみ置き換え。
- 日記の0日目・第1日目の冒頭に、本文に基づく「試したこと」「学び」を追加。新しい記事にも本文で確認できる内容だけを要約する。

### サイトマップ

- `sitemap.xml` にホーム・AIチーム・日記・FAQ・サイト案内の5つの公開URLを列挙。管理用ページ、未完成のページ、日記内アンカーは含めない。人が見る案内は `site-map.html`、検索エンジン向けの一覧は `sitemap.xml` と役割を分ける。
- 公開後のURL：`https://tennistom17-source.github.io/kototoku-web/sitemap.xml`
- 新しいHTMLページを公開した際は、絶対URLの `<url><loc>...</loc></url>` を追加する。自動追加ではない。ページ削除・URL変更時も更新する。
- `lastmod` は実際の更新日を継続管理できる場合のみ記載する。推測の更新日や優先度は設定しない。
- 公開反映を確認してから、所有権を確認済みのGoogle Search Consoleで上記サイトマップURLを送信する。ファイル作成だけでGoogleへの送信が完了するわけではなく、クロール・インデックス登録・順位を保証しない。
- この変更では公開へのpush、Search Consoleへの送信、完了画面の確認は行っていない。

## 確認方法と結果

ビルドや依存パッケージは不要。`index.html` をブラウザで開けば表示できる。
動画を含めた公開時相当の検証には、リポジトリ直下で以下を実行し、`http://127.0.0.1:8765/` を開く。

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

- Chromium / Playwrightで全4ページを320px・390px・1440px幅で確認。横はみ出しなし、メニュー開閉・Escキー操作が正常。
- ホームのPC・スマホのスクリーンショットを目視確認。
- 全4ページの内部リンク、アンカー、画像、CSS、JavaScript、動画参照先を検査し、リンク切れなし。
- 初回表示・動画位置までのスクロールでMP4リクエスト0件。サムネイルの取得・寸法を確認。
- ローカルHTTP配信で動画の再生・シークを確認。動画通信を失敗させた場合のエラー案内も確認。
- 公開HTMLの本文に運用ルールで禁止されている表現がないことを確認。外部アセットの追加なし。
- HTML / CSS / JavaScriptのエディター診断でエラーなし。

実機のiOS Safari / Android、スクリーンリーダー、公開後のGitHub Pagesでの再生は未確認。
エディター内ブラウザでは `file://` から動画を読み込めなかったため、動画の再生検証には上記ローカルHTTP配信を使用した。
